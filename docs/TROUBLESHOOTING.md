# 故障排查

本文面向从源码构建项目的贡献者。仅安装发布补丁时，请参阅[安装补丁](INSTALL.md)。

## `source ROM SHA-256 mismatch`

源 ROM 与 `project.json` 中的固定版本不匹配。常见原因包括：

- 选择了已修改或已打补丁的 ROM；
- 选择了压缩包而不是 `.nds` 文件；
- ROM 经过裁剪或修复；
- 地区或修订版本不同。

重新确认源文件为日版 `ADBJ` Rev 0，并核对 SHA-256。

## `no glyph assignment`

译文包含当前映射和原生日文字库中都不存在的字符。先准备固定版本字体，再重新构建：

```powershell
uv run python tools/fetch_fonts.py
uv run python tools/build_rom.py <原版 ROM> `
  --ark-font-repo work/vendor/ark-pixel-font
```

若上游字体也缺少该字符，应提供经过许可的手工点阵，或在不影响含义的前提下调整译文。

## 文本超出容量

`text_budget_report.tsv` 中的 `remaining_bytes` 为负，或检查报告显示“超长”。构建器不会自动扩展脚本或截断文本。

应精简句式、删除冗余主语或调整分页。不得修改剧情块和指令定位字段绕过检查。

## 中文乱码、黑块或重影

依次确认：

- 构建基于项目指定的字库基线；
- PNG 使用透明背景；
- 字形仅写入颜色索引 0/1；
- 纹理按线性像素而非 tile 顺序处理；
- 模拟器未加载旧 Save State。

## 字形重叠或基线异常

常见原因是可见笔画超过 11×11，或字形位置超出 15×15 映射矩形。不要整体放大字形；应调整单字点阵、`BBX` 偏移或公共基线规则。

## 原生字符被替换

自定义字形覆盖了仍在使用的编码槽。检查：

```text
data/mapping/custom_glyph_map.tsv
data/mapping/font_slots.tsv
```

例如，`97CA` 是“量”的原生槽，不得分配给“只”。修复后应重新运行字形冲突检查和完整构建。

## 中文段落后运行中断

检查脚本是否：

- 改变命令长度或剧情块偏移；
- 未更新文字有效字节数；
- 写入了超出容量的译文；
- 通过旧 Save State 恢复了不兼容的内存状态。

当前构建器保持固定布局并自动更新有效长度字段。若使用项目构建链仍可复现，请附事件 ID、脚本代码和构建报告提交 Issue。

## 资源无法写回原位置

构建器会将体积增长的资源搬移到 ROM 尾部并更新 FAT。若尾部空间不足，应减少资源体积、改善压缩，或在充分验证后实现完整 ROM 重排。

## BPS 应用失败

BPS 会校验源文件大小和 CRC。请确认补丁版本与源 ROM 的 SHA-256 完全匹配，并排除下载损坏。

## 预览与游戏显示不一致

预览按字库映射中的实际矩形宽度步进：双字节字形通常为 15 像素，单字节字形通常为 9 像素。预览不模拟窗口裁剪、字符动画、缩放和最终调色效果，应以模拟器和真实硬件结果为准。
