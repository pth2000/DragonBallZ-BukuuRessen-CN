# 资料模式角色卡

构建链的最后一个阶段，覆盖 37 个角色组、195 项纹理。

```text
romdata/data/DataModeDataImage.bin      日文
romdata/data/DataModeDataImage_EN.bin   英文参考
```

日版资源按 `JA\<角色代码>\data_<角色代码>_<项目>.ntft` 命名。

## 图像格式

4bpp 线性像素纹理，不采用 8×8 图块重排，固定宽度 256 像素：

| 项目 | 尺寸 |
| --- | --- |
| `ex1..ex4` | 256×64 |
| `name`、`team*` | 256×32 |
| `sp*` | 通常为 256×128 |
| `tsh/sp1`、`1617/sp1`、`zbdd/sp1` | 256×256，各含两个支援角色面板 |
| `face` | 角色图像，保持原样 |

全部角色共用存放在 `JA\gkn` 下的一组调色板：`ex2` 与 `ex3` 使用 `ex1` 调色板，全部 `sp*` 使用 `sp1` 调色板，全部 `team*` 使用 `team1` 调色板。索引约定为 `0` 透明、`1` 黑、`13` 黄、`15` 白。究极技说明栏使用原卡片的橙色索引，其余招式使用黄色索引。

## 排版

卡片布局紧凑，因此排版规则多于其他界面。

方向条件使用“向上时／横向时／向下时”，近身条件使用“靠近对手时”，A→X 按键图标按中文宽度紧随文字排列。

操作条件文字相对日版基线统一上移 1 像素。所有中文通过共享 BDF 加载器按全局字框和单字 `BBX` 归一到公共基线，不在界面构建器中维护“拳”等单字偏移。

特殊能力说明按原卡片以 15 像素行距分行，清除范围不覆盖卡片边框。中文全角感叹号使用原版窄体 UI 字形。

若卡片的实心黑色底边落入通用说明区域，构建器会自动缩短清理区域以保留底边，并将临近底边的单行操作文字同步上移 1 像素，匹配日版基线。若按矩形整体清空，黄色背景会越过卡片边界。

## 数据与构建

译文位于 `data/translation/ui_character_data.tsv`。主字段记录每项纹理的标题与说明，三张双支援纹理使用可选的 `secondary_*` 字段记录下半面板。

```powershell
uv run python tools/build_character_data.py
```

产物输出至 `build/ui_character_data_test/`。除逐卡预览外，还为每个角色生成一张纵向合并检查图。构建器限制修改范围，仅允许表中指定纹理的文字矩形发生变化，并验证归档顺序、BPS 回放和最终 ROM 的文件差异。

原版日英纹理可单独渲染，支持线性、图块及多种布局诊断模式：

```powershell
uv run python tools/render_character_data.py gkn --items ex1 sp1 team1 --linear --tile-columns 32 --combined
```

`--combined` 会将所选项目纵向拼接为一张日英角色检查图，便于整组核对。

## 验收要点

扩展角色时应检查日/英/中预览，并在模拟器中逐项翻页，重点确认长团队技名、按键图标前的留白、特殊能力说明的分行，以及相邻角色切换时的布局一致性。
